## Workflow context (the "why")

I get a trading newsletter at 2:30pm Central each day. Today I paste it into ChatGPT, ask it to distill to a structured plan, then manually re-type the result into this app's admin dashboard and click Send to Telegram. I want to replace steps 2 and 3 with: paste newsletter → Claude parses → I review/edit → save and send. This is replacing my manual daily flow.

The "algorithm ingest" feature we built earlier today (POST /api/levels/ingest, Algorithm Levels admin panel, source="algorithm") stays in the codebase but is dormant — no removal. The new feature is additive and lives alongside it.

### 2. Backend routes

All under existing admin auth middleware.

- `POST /api/admin/parse-newsletter`
  - Body: `{ newsletter_text: string }`
  - Calls Claude via the wrapper (see below), returns the parsed plan JSON + the `prompt_version` used + the `claude_api_call_id`
  - On Claude error: return 502 with descriptive message; do NOT lose the user's input (the frontend still has it)
- `POST /api/admin/save-parsed-plan`
  - Body: parsed plan fields + `edited_fields: string[]` + `claude_api_call_id: number` + `send_telegram: boolean`
  - Inserts row in `plans` with `source = "ai_parsed"`
  - If `send_telegram` is true: calls existing Telegram send pipeline with the new `ai_parsed` variant
  - Returns the saved plan

### 4. System prompt — versioned

- File: `server/lib/prompts/parse-newsletter.ts`
- Export `PARSE_NEWSLETTER_PROMPT_VERSION = "v1.0"` and `PARSE_NEWSLETTER_SYSTEM_PROMPT = "..."`
- When I tune the prompt, I bump the version string. The version flows through `claude_api_calls.prompt_version` and `plans.prompt_version`.
- Prompt content rules (compose these into a coherent system prompt):
  - You extract a structured futures trade plan from a daily newsletter.
  - Read the entire newsletter carefully before extracting.
  - Identify the trading date the plan is for — usually "tomorrow" relative to the newsletter's publication date. If the newsletter explicitly names a date, use it.
  - Levels marked "major" take priority over minor levels.
  - For the 4 supports and 4 resistances: prefer the closest major levels to the current/implied price. Closest = `r1`/`s1`, farthest = `r4`/`s4`. If the newsletter doesn't reference current price, order by absolute price (resistances ascending from r1, supports descending from s1).
  - Bias: read the newsletter's bull case / bear case sections. Output one of `bullish` / `neutral` / `bearish`. Provide 1–2 sentence reasoning.
  - Top long: the highest-conviction long setup the author describes, including entry / stop / target if given.
  - Top short: same for shorts. If the author explicitly states they don't short, return exactly: `"Author does not short, no short trade provided"`.
  - Always call the `submit_trade_plan` tool — never respond with prose.
